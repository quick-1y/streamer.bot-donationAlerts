# Рецепт золотого экспорта Streamer.bot 1.0.7

Этот рецепт нужен один раз. Вы создаёте в Streamer.bot несколько тестовых действий и экспортируете только их в файл `golden-1.0.7.sb`. Сборщик пакета в репозитории копирует из этого файла настоящий формат Streamer.bot 1.0.7 и не придумывает поля сам. Поэтому делайте ровно то, что написано ниже, и ничего больше.

Все имена и тексты ниже нужно вводить в точности как написано (с учётом регистра, пробелов и знака `|`).

## Шаг 0. Подготовка

1. Сделайте резервную копию Streamer.bot (Settings > Backup, или любым привычным способом) и сохраните её ВНЕ папки репозитория. Бэкапы и экспорты Streamer.bot могут содержать секреты.
2. Не вставляйте в тестовые действия реальные сообщения чата, имена аккаунтов, токены или файлы из папки профиля Windows.
3. Файл экспорта вы сохраните в папку `tools/golden/` репозитория. Точный путь к этой папке Claude пришлёт в сообщении вместе с просьбой выполнить рецепт. Больше ничего в эту папку не кладите.

## Шаг 1. Действие `GOLDEN | Runtime`

1. Создайте действие с именем `GOLDEN | Runtime`, группа `Golden`.
2. Добавьте под-действие: Core > C# > Execute C# Code.
3. Поля под-действия:
   - Name: `GoldenRuntime`
   - Description: `golden runtime`
   - включите опцию "Precompile on Application Start"
4. Вставьте в редактор весь текст файла `tools/golden/GoldenRuntime.cs` (замените содержимое редактора целиком).
5. Нажмите Find Refs, затем Compile. Ожидается успешная компиляция без ошибок.
6. Сохраните под-действие и действие.

## Шаг 2. Действие `GOLDEN | Call`

1. Создайте действие `GOLDEN | Call`, группа `Golden`.
2. Добавьте два под-действия Core > C# > Execute C# Method. В обоих выберите код `GoldenRuntime`. В первом метод `GoldenPing`, во втором метод `GoldenFire`, именно в таком порядке.
3. Добавьте два триггера:
   - Core > Streamer.bot Started
   - Core > Streamer.bot Exiting
4. Если триггера Exiting в списке нет, так и запишите: это важная информация (находка F1). Тогда оставьте только триггер Started.

## Шаг 3. Очередь `Golden Queue`

Создайте очередь (Queues) с именем `Golden Queue` и включите у неё Blocking.

## Шаг 4. Действие `SPIKE | On event (dict)`

1. Создайте действие `SPIKE | On event (dict)`, группа `Golden`, очередь `Golden Queue`.
2. Триггер: Custom > Golden > `Golden: Event`. (Он появится после того, как код `GoldenRuntime` скомпилирован и выполнил `Init()`. Если в списке его нет, один раз нажмите Compile в `GoldenRuntime` ещё раз или запустите `GOLDEN | Call` вручную, затем откройте список снова.)
3. Под-действия, строго по порядку:
   1. Core > Misc > Log (уровень Information), текст ровно такой:
      `SPIKE ARGS amount=%spikeAmount% count=%spikeCount% flag=%spikeFlag% text=%spikeText%`
   2. If/Else: переменная `spikeAmount`, условие Greater Than, значение `20`.
      - Then: Log с текстом `SPIKE IF-GT PASS`
      - Else: Log с текстом `SPIKE IF-GT FAIL`
   3. If/Else: переменная `spikeAmount`, условие Equals, значение `22.5`.
      - Then: Log с текстом `SPIKE IF-EQ PASS`
      - Else: Log с текстом `SPIKE IF-EQ FAIL`
   4. If/Else: переменная `spikeFlag`, условие Equals, значение `True`.
      - Then: Log с текстом `SPIKE IF-BOOL PASS`
      - Else: Log с текстом `SPIKE IF-BOOL FAIL`

Если в вашем редакторе переменная указывается со знаками процента (`%spikeAmount%`) или без них, используйте тот вариант, который предлагает сам интерфейс для проверки аргумента.

## Шаг 5. Запуск вручную

1. Один раз запустите действие `GOLDEN | Call` вручную (Test / Run).
2. Откройте журнал (Log) Streamer.bot и посмотрите, какие строки `SPIKE IF-*` появились: `SPIKE IF-GT PASS` или `FAIL`, `SPIKE IF-EQ PASS` или `FAIL`, `SPIKE IF-BOOL PASS` или `FAIL`. Также отметьте, появилась ли строка `SPIKE ARGS ...` и какие значения в ней.
3. Запишите результат: он нужен для шага 9.

## Шаг 6. Поле Description у действий

Если в редакторе действия Streamer.bot 1.0.7 есть поле Description (описание), заполните его текстом `golden description` у каждого из тестовых действий. Запишите: поле есть или нет (находка E8).

## Шаг 7. Необязательно: действие `GOLDEN | Examples`

Этот шаг можно пропустить, Фаза 1 от него не зависит. Он нужен, чтобы заранее получить примеры форматов для будущих шагов. В живой сессии пользователь не нашёл под-действие Comment в списке и не понял, куда должен идти Send Message, поэтому формулировки этого шага для интерфейса 1.0.7 требуют уточнения; Log находится в Core > Misc > Log.

1. Создайте действие `GOLDEN | Examples`, группа `Golden`, без триггеров. Сделайте действие выключенным (disabled).
2. Под-действия:
   1. Comment с текстом `golden comment`
   2. Send Message с текстом `golden test` (НЕ запускайте это действие)
   3. If/Else: `spikeAmount` Greater Than Or Equal `10`, внутри него вложенный If/Else: `spikeAmount` Less Than `100`. В каждой ветке (Then и Else обоих блоков) по одному Log с любым коротким текстом, например `golden nested then`.
   4. Play Sound с файлом `C:\Windows\Media\notify.wav`. Никогда не выбирайте файл из папки профиля пользователя Windows.

## Шаг 8. Экспорт

1. Откройте диалог Export и нажмите Clear.
2. Добавьте ТОЛЬКО:
   - действие `GOLDEN | Runtime`
   - действие `GOLDEN | Call`
   - действие `SPIKE | On event (dict)`
   - действие `GOLDEN | Examples` (если делали шаг 7)
   - очередь `Golden Queue`
3. Заполните метаданные экспорта:
   - Name: `DA Golden`
   - Author: `streamer.bot-donationAlerts`
   - Version: `0.0.1`
   - Description: `golden export for builder templates`
4. Нажмите Export to File и сохраните файл под именем `golden-1.0.7.sb` в папку `tools/golden/` репозитория.
5. Не добавляйте команды, WebSocket-серверы и клиенты, таймеры и любые другие действия.

## Шаг 9. Отчёт в чате

Ответьте в чате по пунктам:

1. Версия Streamer.bot, которая показана в приложении.
2. Был ли триггер Streamer.bot Exiting в списке триггеров (да/нет).
3. Есть ли у действия поле Description (да/нет).
4. Какие строки `SPIKE IF-*` появились в журнале на шаге 5 (например, `GT PASS, EQ PASS, BOOL PASS`), и что было в строке `SPIKE ARGS`.
5. Делали ли шаг 7 (да/нет).

## Шаг 10. Не удаляйте тестовые действия

Оставьте действия и очередь в Streamer.bot, пока Claude не подтвердит, что файл принят. Инструкция живой сессии (план 01-06) скажет, когда их можно удалить.

## Что Claude сделает с файлом

Claude проверит файл командами `python -I tools/build_sb.py audit tools/golden/golden-1.0.7.sb`, `check` и `decode`, покажет вам краткий отчёт (имена, метаданные, список ссылок, тексты сообщений) и закоммитит файл в репозиторий только после вашего явного ответа `commit`.
