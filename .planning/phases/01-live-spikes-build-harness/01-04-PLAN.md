## Planner assumptions (no CONTEXT.md: each one is flagged)

- A1 (adopted): the spike is written for C# 7.3 (no `using var`, no switch expressions, no `??=`, no target-typed `new`, no ranges, no `default` interfaces). F6 tells whether Streamer.bot allows more.
- A2/A3 (open, measured here): named kernel semaphores are process-wide; each code sub-action may live in its own AppDomain. The probes record both without assuming either.
- A8 (adopted with guards): RuntimeInformation, WindowsPrincipal, TcpListener, HttpListener and Semaphore may throw inside Streamer.bot's sandbox, so every probe catches and logs `ERROR method=<name> type=<exception type>` and returns false.
- A11 (open, measured by SpikeFireBackground): TriggerCodeEvent from a pool thread works outside any action.
- Logging uses exception type names and numeric codes only, never exception messages (messages can contain paths or user names).
- The spike files stay in the repo after the phase (RESEARCH Open Question 5); they are never copied into `src/` product code.
- Repo hygiene: commit only spike/DaSpikeA.cs and spike/DaSpikeB.cs by explicit path. Never `git add -A` or `git commit -a`. Staged `.github/ISSUE_TEMPLATE/` deletions and untracked `.idea/` and `.claude/` stay out.
